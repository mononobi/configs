If the system skipped the newer kernel, the kernel package installation was likely 
interrupted and left in an unconfigured state.

Here is how to force the repair:

### 1. Fix Interrupted Packages
An unconfigured kernel is often ignored by the system. Running these commands will 
fix broken installations and usually triggers the missing initramfs generation automatically:

```bash
sudo dpkg --configure -a
sudo apt --fix-broken install
```

### 2. Force Generate for the Specific Kernel
If the steps above did not generate the initramfs for the newer kernel, you must target it manually.

First, list your installed kernels to find the exact version string of the newer, failing one:

```bash
ls /boot/vmlinuz-*
```

Next, force the creation (`-c`) of the initramfs for that specific version 
(replace `<version>` with the exact string you found, such as `6.8.0-40-generic`):

```bash
sudo update-initramfs -c -k <version>
```

### 3. Update GRUB
Refresh the bootloader to ensure it sees the newly created initramfs file:

```bash
sudo update-grub
```

You can now safely reboot into the newer kernel.
